# Feature compatibility matrix

Audit written 2026-08-04 ~03:00 CEST, against the working tree as found. See
"A note on timing" at the bottom of `Design/specs/sync-coverage.md` — the
same caveat about concurrent edits applies here.

**Standard of evidence:** every cell below is backed by a call site outside
the defining file and a route a user can actually reach, or it says
`UNVERIFIED` and why. A file existing, a type compiling, or a green build is
never treated as evidence on its own. Where a gap is deliberate, this
document says so explicitly and cites the reasoning, rather than leaving a
deliberate absence looking the same as an accidental one.

**iPadOS, structurally, first:** the `SoundingTV iOS` app target itself is
built `TARGETED_DEVICE_FAMILY = 1` (iPhone only) in both its Debug and
Release configurations (`project.pbxproj`, the `SoundingTV-iOS/Info.plist`
config blocks) — **not** `"1,2"` (iPhone+iPad). So the app cannot install on
an iPad at all today, independent of any UI question. There is also zero
iPad-idiom-aware code anywhere in the source tree — no
`UIDevice.current.userInterfaceIdiom`, no `horizontalSizeClass` branch, no
`isIPad` check (grepped across `SoundingTV-iOS/Sources` and
`SoundingTV-AppClip/Sources`, zero hits). A 101KB planning document,
`Design/specs/ipad-plan.md`, exists and describes what iPad support *would*
look like — nothing in it has shipped. Every `iPadOS` column below is
therefore **N/A**, not "absent" or "partial," except where a feature is
delivered by something other than the main app binary (the Share extension,
built `"1,2"`, is noted separately where relevant, though it has no host app
to attach to on an iPad that can't install the main app).

## Deliberate absences, restated so they don't get "fixed"

- **DJ hardware/MIDI control is macOS-only on purpose.** A DDJ controller is a desk peripheral; there is no equivalent on an Apple TV remote or a touchscreen, and CLAUDE.md's "no touch UI" rule additionally forecloses building a touch-based substitute on the Mac itself.
- **Decks (the DJ console) is macOS-only on purpose,** and is explicitly exempted from the cross-platform "content components must match" design law — CLAUDE.md calls it out as "Serato/Rekordbox by design," dense and hard-edged, "must never scroll."
- **Top Shelf is a tvOS-only system concept** — there is no equivalent surface on iOS/iPadOS/macOS to compare it against; its `N/A` cells are not gaps.
- **The Share extension and Widgets are iOS-only** because their host — the phone, which is the device most likely to receive a share sheet or sit on a Lock Screen — is the only place they make sense; there's no host app on iPadOS to attach to and no equivalent OS surface on tvOS/macOS for the Share case (macOS does have widgets as an OS concept, but no `SoundingTV-Widget` target membership exists for it in this project — that one is closer to unaddressed than deliberate, and is not claimed as a deliberate absence here).
- **iPadOS is a structural non-target, not a partial one.** Every `N/A` in the iPadOS column reflects `TARGETED_DEVICE_FAMILY = 1` on the app itself, not a UI judgement call.

## What could not be verified, and why

Two table cells are marked `UNVERIFIED` outright:

1. **Spotlight indexing on macOS** — `CSSearchableIndex` exists on macOS in principle; no `SpotlightIndexingService` reference was found under `SoundingTV-macOS/Sources`, but this wasn't chased to full certainty (e.g. a differently-named macOS equivalent was not ruled out).
2. **Top Shelf's actual on-device rendering** — the code path (`ContentProvider.swift` → `DefaultShelf.swift` → real `TopShelfPublisher.publish` call sites) and the entitlement match (`group.red.forbes.sounding` in both `.entitlements` files) are traced and real, but nothing in this environment can drive or screenshot the actual tvOS Home Screen to confirm the shelf renders as designed — the known environment limits (no gesture/press synthesis beyond `XCUIRemote`, which doesn't reach the Home Screen) apply here directly.

Three more cells carry a lower-confidence caveat inline rather than a hard
`UNVERIFIED`, because a definite call could be made but on thinner evidence
than the rest of the matrix:

3. **Analysis production quality/rate on iOS specifically** — described as "plausible" rather than measured; CLAUDE.md's measured facts cover tvOS (fails) and macOS (works) explicitly but not iOS.
4. **Widgets/macOS** — stated as absent based on no `SoundingTV-Widget` target membership found for macOS, but not chased against whether a macOS-native widget extension exists under a different target name.
5. **Peer content serving end-to-end** — the call sites are real and cited, but BACKLOG's claim of prior "independent verification" was relied on rather than re-run in this pass (re-running would mean standing up the local HTTP server + ffmpeg fixture CLAUDE.md documents, which was out of scope for a matrix audit).
